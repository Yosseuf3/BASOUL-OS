# YVL v1.0 Foundation approval checklist

Approval records acceptance of the design authority and its contracts; it does not authorize product migration.

- [ ] Governance ownership, exception process, review evidence, and rollback obligations are approved.
- [ ] Token taxonomy and naming distinguish semantic roles from the approved electric-blue/cyan brand accents.
- [ ] Color combinations meet WCAG 2.2 AA contrast; focus and status do not rely on color alone.
- [ ] Typography roles approve Sora for display and Inter for UI/body without authorizing font installation.
- [ ] Spacing, radii, shadow, and motion scales express consistent structural and interaction semantics.
- [ ] Web and React Native/Expo maps expose every canonical category with documented platform adaptation.
- [ ] Iconography uses geometric outlines, consistent optical weight, accessible labels, and text for unfamiliar actions.
- [ ] HUD and pattern motifs remain functional, sparse, low-noise, and subordinate to content.
- [ ] Social rules require approved marks, rights-cleared sources, accessible contrast, and platform-safe layouts.
- [ ] Accessibility requirements cover keyboard focus, contrast, readable hierarchy, non-color state communication, and responsive behavior.
- [ ] RTL readiness covers logical layout, bidirectional icon review, mirrored directional motion, and text alignment.
- [ ] Reduced-motion behavior removes non-essential animation and preserves comprehension.
- [ ] Generated CSS, TypeScript, and native artifacts match canonical JSON byte-for-byte.
- [ ] The deterministic showcase remains outside application, public, mobile, production routes, and runtime bundles.
- [ ] Adoption rollback keeps legacy values until verified parity and defines bounded reversal points.
- [ ] Production is unchanged: no runtime styles, routes, fonts, product behavior, data, APIs, auth, deployment, or naming changed.
